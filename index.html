01 / Greedy Method

Choose well.
Repeat.

Greedy algorithms construct a solution by repeatedly making the best feasible local choice.

What is the Greedy Method?

Exam definition: The greedy method is an algorithmic technique that constructs a solution step-by-step by selecting the locally optimal feasible choice at each stage, with the aim of obtaining a globally optimal solution.

Simple idea

Imagine you need to make a decision repeatedly. At every step, instead of considering every possible future combination, greedy says:

Choose the best option available RIGHT NOW.

Then continue with the remaining problem.

Local vs Global Optimum

  • Local optimum: best choice at the current step.
  • Global optimum: best complete solution.
A locally optimal choice does NOT always produce a globally optimal solution. Greedy must only be used when the problem has the required properties.

Greedy-Choice Property

A problem has the greedy-choice property when a globally optimal solution can be obtained by making an appropriate locally optimal choice first.

Optimal Substructure

A problem has optimal substructure if an optimal solution contains optimal solutions to its relevant smaller subproblems.

General process

S = empty solution

while candidates remain:

    select the best candidate

    if candidate is feasible:
        add candidate to S

return S

Important terms

  • Candidate set: available choices.
  • Selection function: chooses the best candidate.
  • Feasibility function: checks whether it can be used.
  • Objective: maximize or minimize something.

Applications in this unit

  • Fractional Knapsack
  • Huffman Coding
  • Job Sequencing
  • Minimum Spanning Tree
  • Dijkstra's Algorithm
What to write for a 5-mark theory question: Definition → greedy-choice property → optimal substructure → general procedure → one example/application → complexity discussion.

Problem

You have items with weights and profits and a knapsack with limited capacity. Maximize total profit without exceeding the capacity. Items may be divided into fractions.

Greedy rule

Profit / Weight = profit obtained per unit weight

Calculate this ratio for every item and sort in descending order. Take as much as possible from the item with the highest ratio.

Fractional vs 0/1

Feature Fractional 0/1
Split item? Yes No
Greedy? Yes Not generally
Common approach Greedy Dynamic Programming

Worked example

Item Weight Profit P/W
A10606
B201005
C301204

Capacity = 50 kg

Order: A → B → C

  • Take all A: 10 kg, profit = 60, remaining = 40.
  • Take all B: 20 kg, profit = 100, remaining = 20.
  • C weighs 30 kg but only 20 kg fits.
  • Take 20/30 of C.
Profit from C = 120 × (20/30) = 80
Total profit = 60 + 100 + 80 = 240

Algorithm

1. Calculate profit/weight.
2. Sort in decreasing ratio.
3. Start with empty knapsack.
4. Take complete item if it fits.
5. Otherwise take the fraction that fits.
6. Stop when capacity is full.

Complexity

Calculating ratios: O(n)
Sorting: O(n log n)
Selection: O(n)

Overall: O(n log n)
Common mistake: "Fractional" does not mean you can take unlimited amounts of an item. You can only divide the quantity that actually exists.

What is Huffman Coding?

Huffman coding is a greedy lossless compression technique that creates variable-length, prefix-free binary codes based on symbol frequencies.

Main idea

  • Frequently occurring symbols get shorter codes.
  • Rare symbols get longer codes.
  • Codes are prefix-free.

Greedy rule

Repeatedly combine the TWO LOWEST frequencies.

Complete example

Character Frequency
A5
B9
C12
D13
E16
F45

Combine the two smallest repeatedly:

5 + 9   = 14
12 + 13 = 25
14 + 16 = 30
25 + 30 = 55
45 + 55 = 100

                          25    30
                         / \   / \
                      C(12) D(13) 14 E(16)
                                  / \
                                A(5) B(9)

Assign 0 to left and 1 to right. Then trace from the root to each character.

Prefix-free

No complete code is the prefix of another complete code. This makes decoding unambiguous.

Complexity

O(n log n)

Using a min-heap / priority queue.

Numerical question method: Write frequencies → repeatedly select two smallest → combine → reinsert → repeat → draw tree → assign 0/1 → trace codes.

Problem

Given jobs with deadlines and profits, where each job takes one unit of time, schedule jobs to maximize total profit while completing every selected job before or at its deadline.

Greedy rule

  1. Sort jobs by decreasing profit.
  2. Take the most profitable job first.
  3. Place it in the latest free slot ≤ its deadline.

Why the latest slot?

Putting a job as late as possible preserves earlier slots for jobs having earlier deadlines.

Example

Job Deadline Profit
J12100
J2119
J3227
J4125
J5315

Sort by profit:

J1 → J3 → J4 → J2 → J5

Maximum deadline = 3, therefore:

Slot 1 | Slot 2 | Slot 3

J1 → slot 2
J3 → slot 1
J4 → no slot
J2 → no slot
J5 → slot 3 

Slot 1 | Slot 2 | Slot 3
  J3   |   J1   |   J5
Total profit = 27 + 100 + 15 = 142

Pseudocode

sort jobs by decreasing profit

create empty slots

for each job:
    for t = deadline down to 1:
        if slot[t] is empty:
            slot[t] = job
            break

Complexity

O(n²)

For the basic implementation where we search backwards for a free slot.

Common mistake: Don't place the highest-profit job in the earliest free slot. Always try the latest available slot before its deadline.

First understand: Graph

A graph consists of vertices and edges. In a weighted graph, each edge has a value such as cost, distance or time.

Spanning Tree

A spanning tree is a subgraph that connects all vertices of a connected graph without containing any cycle.
For n vertices → exactly n − 1 edges

Minimum Spanning Tree

An MST is a spanning tree whose total edge weight is minimum among all possible spanning trees.

Important properties

  • Connects every vertex.
  • Contains no cycle.
  • Contains exactly V − 1 edges.
  • Applies to connected weighted undirected graphs.
  • There can be multiple MSTs with the same total weight.

Prim

Starts with one vertex and repeatedly adds the cheapest edge that connects the current tree to an unvisited vertex.

Kruskal

Sorts all edges by increasing weight and repeatedly selects the cheapest edge that does not create a cycle.

Core idea

Start at a vertex → choose cheapest outgoing edge → add new vertex → repeat

Execution example

       2
   A-------B
   |       |
  6|       |3
   |       |
   C-------D
       1

Start at A.

  1. A → cheapest edge is A-B = 2.
  2. Current tree = A,B. Cheapest edge leaving it = B-D = 3.
  3. Current tree = A,B,D. Cheapest edge to new vertex = D-C = 1.
MST weight = 2 + 3 + 1 = 6

Algorithm

Choose starting vertex.

While not all vertices are included:

    find minimum-weight edge
    connecting tree to an
    unvisited vertex

    add edge and vertex

Memory trick

Prim = Grow.
Always think about the current tree and its cheapest way to reach a new vertex.

Complexity

With adjacency matrix/simple implementation:

O(V²)

With a binary heap and adjacency list, it can be:

O(E log V)
For an exam numerical: mark the starting vertex, list the candidate outgoing edges at every step, circle the chosen minimum, then calculate the final total.

Core idea

Sort ALL edges → take cheapest edge → reject if it creates a cycle

Execution

  1. List every edge.
  2. Sort edges by increasing weight.
  3. Take the smallest edge.
  4. Check whether it creates a cycle.
  5. If no cycle, add it.
  6. Continue until V − 1 edges are selected.

Cycle detection

If the two endpoints of an edge are already connected through selected edges, adding that edge creates a cycle.

Cycle → reject the edge.

Example

       2
   A-------B
   |       |
  6|       |3
   |       |
   C-------D
       1
Edge Weight Action
C-D 1 Take
A-B 2 Take
B-D 3 Take
A-C 6 Stop — already V−1 edges
MST = {C-D, A-B, B-D}, weight = 6

Prim vs Kruskal

PrimKruskal
Starts with vertexStarts with edges
Grows one treeBuilds components initially
Cheapest outgoing edgeCheapest global edge
New vertexNo cycle

Complexity

O(E log E)

Main reason: sorting the edges. Since E is at most roughly V² in a simple graph, this is also commonly written as O(E log V).

What problem does Dijkstra solve?

Given a weighted graph and one starting vertex (source), Dijkstra's algorithm finds the shortest distance from that source to every other reachable vertex.

Critical restriction

Dijkstra's algorithm does not work correctly with negative edge weights.

Key idea

At every step, select the unvisited vertex having the smallest currently known distance from the source. Once finalized, its shortest distance is known.

Relaxation

Suppose we know the distance to A and there is an edge A → B. We test whether going through A gives a shorter route to B.

newDistance = distance[A] + weight(A,B)

If newDistance is smaller than the current distance[B], update distance[B].

Worked example

        4
   A---------B
   |         |
  2|         |1
   |         |
   C---------D
        3

Also:
B-C = 5

Start = A.

Vertex Initial distance
A0
B∞
C∞
D∞

Step 1: A is smallest. Finalize A.

From A:

  • B = 0 + 4 = 4
  • C = 0 + 2 = 2

Step 2: C has smallest distance = 2.

From C: D = 2 + 3 = 5

Step 3: B has distance 4.

From B: D = 4 + 1 = 5, so D remains 5.

Final distances: A=0, C=2, B=4, D=5

Algorithm

distance[source] = 0
all other distances = infinity

repeat:

    choose unvisited vertex
    with smallest distance

    mark it visited

    for every neighbour:

        calculate alternative distance

        if alternative is smaller:
            update distance

Complexity

Simple array / adjacency matrix:

O(V²)

Binary heap implementation:

O((V + E) log V)
Don't confuse Dijkstra with Prim.

Prim minimizes the cost of a network connecting all vertices. Dijkstra minimizes distance from ONE SOURCE to each vertex.

What to analyze?

  • Does the greedy choice lead to an optimal solution?
  • Does the problem have optimal substructure?
  • What is the time complexity?
  • What data structure is used?

Advantages

  • Usually simple to understand.
  • Often efficient.
  • Usually requires less computation than brute force.

Limitations

  • Does not work for every optimization problem.
  • Local optimum can lead to a non-optimal final solution.
  • Correctness must be established for the particular problem.

02 / Backtracking

Try.
Reject.
Go back.

Backtracking systematically searches through possible solutions while abandoning a partial solution as soon as it violates a constraint.

Basic idea

Backtracking is a systematic search technique that constructs a solution incrementally and abandons a partial solution as soon as it is determined that it cannot lead to a valid solution.

Simple mental model

Choose → Check → Continue OR Undo → Try another choice

Example

Imagine a maze. You move forward. If you reach a dead end, you go backward to the previous decision point and try another path.

Generic pseudocode

BACKTRACK(solution):

    if solution is complete:
        report solution
        return

    for each possible choice:

        if choice is valid:

            make choice

            BACKTRACK(solution)

            undo choice

State-space tree

Every node represents a partial solution. Each branch represents a possible next decision.

Pruning

Pruning means stopping exploration of a branch when we already know that branch cannot produce a valid solution.

Exam definition: Backtracking solves constraint problems by constructing candidates incrementally and abandoning a candidate as soon as it fails to satisfy the constraints.

Problem statement

Place eight queens on an 8 × 8 chessboard so that no two queens attack each other.

Queens attack along

  • Same row
  • Same column
  • Same diagonal

Backtracking strategy

Usually place one queen per row. For each row, try columns one by one. If a position is safe, place the queen and move to the next row. If no column works, go back to the previous row.

Safety conditions

For a new queen at (row, column):

  • No previous queen in the same column.
  • No previous queen on the same diagonal.
Same diagonal if |r1 − r2| = |c1 − c2|

Example solution

. Q . .
. . . Q
Q . . .
. . Q .

The 4 × 4 example demonstrates the same principle used for 8 queens. Each row has one queen and no two attack each other.

Algorithm

solve(row):

    if row == N:
        return true

    for col = 0 to N-1:

        if position is safe:

            place queen

            if solve(row + 1):
                return true

            remove queen

    return false

Complexity

The naive search can be exponential. A common upper-bound description for N-Queens is O(N!), depending on the formulation/pruning.

For mid-sem, focus more on the backtracking procedure and board execution than on deriving an exact tight complexity bound.
Numerical/trace question: Draw the board after every placement and mark where backtracking occurs. Do not simply write the final arrangement.

Problem

Given a graph and m colors, assign a color to every vertex such that no two adjacent vertices have the same color.

Example

A ----- B
|       |
|       |
C ----- D

If A and B are adjacent, they cannot have the same color. Likewise for every connected pair.

Backtracking idea

  1. Start with the first vertex.
  2. Try color 1.
  3. If valid, continue.
  4. If invalid, try another color.
  5. If no color works, backtrack.

Safety condition

A color can be assigned to vertex v only if none of v's already-colored neighbors has that color. 

color(v) is safe
if for every adjacent u:
    color[u] != color[v]

Pseudocode

colorVertex(v):

    if v == V:
        return true

    for c = 1 to m:

        if safe(v,c):

            color[v] = c

            if colorVertex(v+1):
                return true

            color[v] = 0

    return false

Complexity

O(m^V)

In the worst case, each of V vertices can try m colors.

Remember: Graph coloring asks "which color can this vertex safely take?" If no color is possible, backtrack.

Definition

A Hamiltonian cycle is a cycle in a graph that visits every vertex exactly once and returns to the starting vertex.

Important distinction

A Hamiltonian cycle focuses on visiting every vertex exactly once.

An Eulerian cycle focuses on visiting every edge exactly once.

Backtracking approach

  1. Choose a starting vertex.
  2. Add an adjacent unvisited vertex.
  3. Continue building the path.
  4. Reject a vertex if it is already used.
  5. If all vertices are included, check whether the last vertex connects to the start.
  6. If not, backtrack.

Validity conditions

A candidate next vertex must:

  • Be adjacent to the current vertex.
  • Not already appear in the path.
  • At the end, connect back to the starting vertex.

Pseudocode

hamiltonian(pos):

    if pos == V:
        return edge(last, start)

    for each vertex v:

        if safe(v):

            path[pos] = v

            if hamiltonian(pos+1):
                return true

            remove v

    return false

Complexity

O(V!)

Worst-case backtracking search is exponential/factorial in nature.

Memory trick: Hamiltonian = every vertex once + return home.

Why can it be expensive?

Backtracking may have to explore a large number of possible combinations. In the worst case, the search tree grows exponentially.

Why is it still useful?

It avoids exploring branches that are already known to be invalid. This is called pruning.

Search tree

                    Start
                  /   |   \
                 A    B    C
                / \       / \
               X   Y     X   Y
              /
         invalid → prune

Instead of exploring every possible branch, the algorithm cuts off invalid branches as early as possible.

Typical complexities

ProblemTypical worst-case idea
Graph ColoringO(m^V)
Hamiltonian CycleO(V!)
N-QueensExponential / often bounded by O(N!) for search formulations

Advantages

  • Simple way to solve constraint problems.
  • Can find one or all solutions.
  • Pruning can dramatically reduce actual work.

Disadvantages

  • Worst-case runtime can be extremely high.
  • Not suitable for very large search spaces without strong pruning.
